1. Цель работы

Модернизировать приложение FastAPI для полного набора операций CRUD, сформировать ответы с помощью Pydantic и реализовать обработку ошибок с корректными HTTP-кодами. Персонализировать прикладные сообщения для разработчика Егора и проверить работу API реальными запросами curl.

2. Среда и запуск

Среда фактической проверки: Linux, Python 3.14.4; fastapi 0.143.3, pydantic 2.14.1, uvicorn 0.54.0. Зависимости установлены в локальное виртуальное окружение. Точный состав окружения сохранён в results/requirements-tested.txt.

Сервер и клиент запускаются в разных терминалах, как требуется методичкой. Для проверки выбран порт 8001: на порту 8000 уже работала исходная версия приложения. Все приведённые ниже результаты относятся к обновлённой версии на 8001.

python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
uvicorn api:app --host 127.0.0.1 --port 8001

Во втором терминале:

python3 verify_curl.py http://127.0.0.1:8001

Сценарий вызывает установленную программу curl и проверяет HTTP-коды и содержимое JSON. Перед проверкой он очищает список задач. Swagger UI доступен по адресу http://127.0.0.1:8001/docs, схема — http://127.0.0.1:8001/openapi.json.

3. Выполненная модернизация

В model.py добавлены TodoItem для изменения текста задачи и TodoItems для списка задач без идентификаторов. Модель Todo по-прежнему содержит id и item. Примеры схем заданы через ConfigDict(json_schema_extra=...), поскольку установлен Pydantic 2; это современный эквивалент Config.schema_extra из методички.

class TodoItem(BaseModel):
    item: str

class TodoItems(BaseModel):
    todos: list[TodoItem]

В todo.py добавлены PUT /todo/{todo_id}, DELETE /todo/{todo_id} и DELETE /todo. Создание задачи возвращает 201 Created. Успешные чтение, обновление и удаление возвращают 200 OK. PUT меняет только item, сохраняя id.

@todo_router.get("/todo", response_model=TodoItems)
async def retrieve_todos() -> dict:
    return {"todos": todo_list}

Модель ответа фильтрует id только при выдаче общего списка. GET /todo/{todo_id} возвращает полную задачу с идентификатором.

Для отсутствующей задачи при GET, PUT и DELETE генерируется HTTPException с кодом 404. Прикладные сообщения содержат имя Егора. Дополнительно предотвращено создание задач с повторным ID: такой запрос возвращает 409 Conflict, чтобы обращение по идентификатору было однозначным.

raise HTTPException(
    status_code=status.HTTP_404_NOT_FOUND,
    detail="Егор, задача с указанным ID не найдена.",
)

Неверный тип ID в пути и отсутствие обязательного поля item обрабатываются стандартной валидацией FastAPI/Pydantic: HTTP 422 с описанием в detail. Системные сообщения валидатора сохранены в стандартном формате.

6. Результаты проверки и вывод

Успешно проверены 23 запросов curl. Подтверждены создание задачи с кодом 201, чтение списка без ID, чтение одной задачи с ID, изменение текста без изменения ID, удаление одной и всех задач. Все три операции над отсутствующей задачей возвращают 404. Повторный ID возвращает 409 и не меняет список. Некорректные запросы возвращают 422 и не добавляют данные.

Дополнительно через curl получена схема OpenAPI: проверена ссылка GET /todo на TodoItems, документирование ответа 201 для POST и наличие примера TodoItem. Копия схемы находится в results/openapi.json.

Задачи хранятся в памяти одного процесса, поэтому после перезапуска сервера список очищается. Для учебной демонстрации используется один worker. Dockerfile сохранён; проверка выполнена локально через Uvicorn, сборка Docker не проводилась.

Приложение реализует требования методички по CRUD, моделям ответов, обработке ошибок и персонализации сообщений. Исходные файлы api.py, model.py, todo.py и requirements.txt находятся рядом с отчётом; README.md содержит команды запуска и таблицу маршрутов.
