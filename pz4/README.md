# Практическая работа: CRUD, модели ответов и обработка ошибок

Основание: `ПЗ№4-1.pdf`. Внутренний заголовок PDF — «Практическое занятие №5»;
название исходного приложения «Практическая работа №4» сохранено.

## Запуск

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
uvicorn api:app --host 127.0.0.1 --port 8000
```

Swagger UI: http://127.0.0.1:8000/docs.
Схема OpenAPI: http://127.0.0.1:8000/openapi.json.

Docker (при наличии работающего Docker):

```bash
docker build -t egor-todo .
docker run --rm -p 8000:8000 egor-todo
```

## Проверка

Во втором терминале из каталога проекта:

```bash
python3 verify_curl.py
```

Если порт 8000 занят, запустите Uvicorn с `--port 8001`, а проверку — командой
`python3 verify_curl.py http://127.0.0.1:8001`. Фактическая проверка для отчёта
выполнена на порту 8001, поскольку на 8000 уже работала исходная версия.

Проверка выполняет реальные запросы через `curl`, проверяет коды HTTP и JSON,
сохраняет протокол в `results/curl-transcript.txt`, структурированные результаты
в `results/curl-results.json` и схему в `results/openapi.json`.
**Сценарий очищает все задачи**: запускайте его на учебном экземпляре приложения.

| Метод | Путь | Результат |
|---|---|---|
| GET | `/` | Персонализированное приветствие, 200 |
| POST | `/todo` | Создание `{id, item}`, 201; повторный ID — 409 |
| GET | `/todo` | Список только с `item`, без `id`, 200 |
| GET | `/todo/{todo_id}` | Одна задача с `id` и `item`, 200 или 404 |
| PUT | `/todo/{todo_id}` | Обновление `item` без изменения ID, 200 или 404 |
| DELETE | `/todo/{todo_id}` | Удаление одной задачи, 200 или 404 |
| DELETE | `/todo` | Удаление всех задач, 200 |

Неверный тип ID и отсутствие обязательных полей дают стандартный ответ FastAPI
с HTTP 422 и полем `detail`. Прикладные сообщения персонализированы для Егора.
Задачи хранятся в памяти одного процесса и пропадают при его перезапуске.
Для демонстрации используйте один worker.

`TodoItem` и `TodoItems` используют `ConfigDict(json_schema_extra=...)`, совместимый
с Pydantic 2, вместо устаревшего `Config.schema_extra` из методички.
